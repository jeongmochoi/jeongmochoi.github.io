- 예제 CV를 읽던 `jekyll_get_json` 설정과 예제 소셜 계정을 함께 정리했다. 검증된 Google Scholar 계정 `xHzl8QQAAAAJ`는 유지한다.
- 원본 테마 README용 미리보기, 테마 사이트의 Lighthouse 보고서, 원본 테마 운영용 이슈·릴리스·stale 설정을 제거했다.
- 삭제한 예제 페이지를 전제로 하는 테스트와 오래된 `gh-pages` 수동 배포 스크립트를 제거했다. 현재 홈페이지용 SEO 검사, 인용 검사, 화면·링크 검사 및 사용 중인 통합 검사는 유지한다.

삭제 파일은 총 138개이며, 파일별 목록은 이 PR의 Files changed에서 확인할 수 있다. Git 이력을 지우거나 다시 쓰지 않았으므로 기존 커밋에서 복구할 수 있다.

## 알림과 실행 횟수

기존 워크플로 YAML 20개를 8개로 줄였다. 이미 원본 테마 소유자 조건으로 건너뛰던 Docker/Lighthouse/외부 링크 검사, 미사용 CV 렌더링·목차 갱신·과거 HTML 검사·Copilot 준비·옛 접근성 검사 등을 제거했다. 별도 링크/업그레이드 검사 워크플로는 PR 빌드 검사로 통합했다.

| 남겨 둔 자동화         | 실행 목적                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| `site-pr-checks.yml`   | 모든 PR의 빌드, SEO/PDF 정책, 테마 계약·업그레이드 및 로컬 링크 검사. 필수 `site-build` 상태 이름 유지 |
| `deploy.yml`           | 승인된 `main` 변경의 빌드와 GitHub Pages 배포. PR 중복 빌드 제거; 강의 PDF와 robots.txt 변경도 감지    |
| `pr-preview.yml`       | 관련 페이지 변경의 데스크톱·모바일 미리보기와 전체 HTML 감사                                           |
| `prettier.yml`         | 변경한 파일의 서식 검사                                                                                |
| `citation-checks.yml`  | 인용 데이터·계정·실패 처리 검증                                                                        |
| `update-citations.yml` | 기존 일정의 Scholar 갱신 Draft PR 작성                                                                 |
| `codeql.yml`           | 기존 코드 보안 검사와 주간 검사                                                                        |
| `unit-tests.yml`       | 설정·의존성·CSS·통합 테스트 변경 시 검사 또는 수동 실행. 일반 글/데이터 변경과 main 중복 실행 제외     |

최근 실패 이력에는 실제 빌드·서식·미리보기 실패도 있었다. 파일 정리만으로 모든 알림이 없어지는 것은 아니며, 필요한 검사 실패 알림과 보안 알림은 유지한다. 계정의 알림 수신 설정은 변경하지 않았다. 변경은 PR 승인·병합 후 적용된다.

## 보존 및 검증

- 실제 강의 PDF 410개와 국문·영문 강의 페이지를 모두 보존한다. 기존 PDF 총 412개 중 제거하는 2개는 `example_pdf.pdf`와 `Albert_Einstein_CV.pdf`다.
- 실제 공개 페이지, 논문 목록, 레이아웃, 스타일, 국기 이미지, Google 소유권 인증 파일, robots.txt는 원본 바이트를 유지한다.
- GitHub Pages 배포 권한, main 보호 규칙, 필수 `site-build` 검사 및 승인 후 배포 원칙을 유지한다.
- `test/`, 에이전트 안내, Python 의존성 목록을 사이트 출력에서 제외해 개발용 파일이 공개 산출물에 복사되지 않게 한다.
- 빌드·SEO·로컬 링크·화면 검사 결과는 PR의 Checks와 화면 검사 아티팩트에서 확인한다. 검증의 실제 성공/실패 상태는 PR 설명에 기록한다.
